# 路径运动与网页面板

## 先独立查看路线

```powershell
.\.venv\Scripts\python.exe main.py --route-panel --route-file route.example.json
```

打开终端打印的 `http://127.0.0.1:8765/#...` 完整链接。
独立模式无需打开微信，不进行注入。网页可导入路线、预览运动、调整参数。

## 向小程序推送运动位置

先退出独立面板进程，再运行：

```powershell
.\.venv\Scripts\python.exe main.py -x --panel --route-file route.example.json --debug
```

也可省略 `--route-file`，在网页中选择路径文件。
需要自定义精度、海拔时可附加 `--location-file location.example.json`。
端口被其他进程占用时，可用 `--panel-port 8766`。

路径加载时就启用模拟定位，位置固定在第一个点，速度为 0，不需要先点击网页开始。
等 `script loaded` 后重新打开目标小程序，确认面板右上方有定位接口确认，
再在运动记录软件中开始记录，最后按需点击网页“开始 / 继续”让位置移动。
如果未通过 `--route-file` 指定路径，则需先在网页导入文件才能确定起点。
网页中的运动轨迹是后端生成值，
不是小程序实际接收值；断线或未完成注入时，路线仍可预览，不代表定位已生效。
本功能沿用现有 wx 定位模拟通道，其覆盖范围和限制见 [定位说明](location.md)。

## 文件格式

推荐 JSON（纬度、经度使用显式字段）：

```json
{
  "name": "我的路线",
  "coordinateSystem": "gcj02",
  "points": [
    {"latitude": 31.319498, "longitude": 121.392710},
    {"latitude": 31.320498, "longitude": 121.392710},
    {"latitude": 31.320498, "longitude": 121.394710}
  ]
}
```

`coordinateSystem` 支持 `wgs84` / `gcj02`，普通 JSON 未指定时默认 `gcj02`。
点列表也可写为 `[[121.392710,31.319498],[121.392710,31.320498]]`，
数组顺序固定为 **[经度, 纬度]**。

支持 GeoJSON LineString，以及只包含一条 LineString 的 Feature / FeatureCollection。
GeoJSON 按 WGS84 解释。普通 JSON 的 `points` 保留原始点序，相邻点直线连接。
路径需要 2–10000 个点，文件最多 1 MB（网页导入），连续重复点会合并；
总长至少 1 米。路线使用局部米制投影，限制在起点周围 100 km、纬度 ±85°以内，
适用于本地步行/跑步路线，不用于跨日期变更线或长途测绘。

## 运动规则

- 默认沿路线速度 12 ± 3 km/h，即 9–15 km/h。随机目标每 2–5 秒更新，速度平滑过渡。
- 横向随机目标位于路线左右 0–3 米，以平滑过渡模拟漂移；临近标记点时逐渐回到点位，
  避免折线拐弯处跳动。显示速度为沿路线前进速度，不含微小横向漂移分量。
- 默认不循环。勾选循环并“应用参数”后，终点直接跳回起点继续，不生成返程线。
- 非循环到达终点时保持终点，速度为 0。点击开始会从起点重新运动。
- 暂停保持当前位置并将速度设为 0；继续从当前进度恢复。
- 回到起点会清零进度和圈数，并立即启用起点静止定位，等待点击开始移动。
- 停止模拟会关闭定位替换，恢复原定位调用。恢复持续定位监听的方法见定位说明。
- 导入另一条路线时直接切换到新起点并保持静止，不会短暂恢复真实位置。
  参数修改需点击“应用参数”。

## 手机朝向

默认选中“自动沿路径切线”：用当前路段的方向近似手机朝向，忽略随机 GPS 漂移。
北为 0°、东 90°、南 180°、西 270°。到拐点后切换到下一段切线；终点保持最后一段方向。
起点静止时使用第一段方向，暂停时保持当前路段方向。
面板的箭头和角度显示此模拟值。也可选择“手动固定角度”，输入 0–360°后应用。

朝向通过存在且可写的 `wx.startCompass` / `wx.stopCompass` /
`wx.onCompassChange` / `wx.offCompassChange` 接口组模拟，罗盘事件每秒 5 次。
它是根据路径估算的方位角，不包含手机倾斜、陀螺仪或真实磁偏角。
如果当前环境缺少罗盘接口，面板会显示未确认，日志会说明原因；定位继续运行。

桌面地图额外使用蓝点适配器显示朝向：不依赖渲染层提供罗盘 API，也不要求业务
注册 `onCompassChange`。蓝点在导入路线后立即静止于起点，移动时跟随当前坐标。
面板分别显示地图蓝点同步数量、朝向箭头数量和逻辑层罗盘监听数；仅看到“定位接口
已确认”不代表地图绘制已适配。详情见 [蓝点适配说明](location.md#蓝点不移动朝向不显示桌面地图)。

运动在 Node 后端执行，网页刷新或关闭不会使其暂停；停止需用按钮或退出脚本。
系统长时间休眠期间不累计大段位移。每秒左右向定位服务发送位置，实际小程序
接收频率受调试连接和业务调用频率影响。网页约每半秒刷新，显示最近 2000 个轨迹点。

运动设置和进度存于当前进程内，重启后恢复默认；路径文件不会被覆盖。
路线加载后优先于固定位置配置；停止后恢复原定位，若要重新使用固定配置请
重新启动不带路径参数的旧命令。

网页为本机离线路线图，不加载在线地图底图，文件内容不发往第三方服务。
面板只监听 127.0.0.1，需使用本次启动打印的含访问码的链接。

本次仅完成类型/语法检查，未进行微信实机验证。

## 注入标识

小程序连接注入服务后，页面右下角显示蓝色两行小字 `SHUAutoRun` / `controlled`。
标识不拦截点击，暂停或停止路径模拟时仍保留；不带路径面板的普通注入也会显示。
它只表示调试注入连接，不能代替定位、蓝点或罗盘的生效状态。
退出脚本或断开连接约 30 秒后移除（页面暂停执行时需等恢复执行）。
